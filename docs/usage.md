# 使用手册

本手册面向第一次使用 LanRoom 的用户。先按[首页](../README.md)启动服务端；部署和维护见[部署指南](deployment.md)。全文中的 `192.168.1.10` 都是示例，应替换为电脑的真实局域网 IP。

## 1. 启动并确认服务可用

电脑运行 `go run .`，或启动 Linux host Compose。电脑浏览器打开 `http://127.0.0.1:8787`，应看到 LanRoom 页面；终端需保持运行。可用以下命令检查 HTTP 接口：

```bash
curl --fail http://127.0.0.1:8787/api/info
```

返回 JSON 说明 HTTP 服务可用，不代表手机 UDP 自动发现已通过。若打不开，先看[排错指南](troubleshooting.md)。

## 2. 手机或另一台电脑加入

### 使用网页

在电脑页面点击「让其他设备加入」，手机扫描二维码，或在另一台设备输入 `http://192.168.1.10:8787`。不要把电脑的 `localhost` 或 `127.0.0.1` 地址输入手机。

设置昵称并加入后，应看到连接状态和在线设备。启用口令时按提示输入；已登录网页展示的加入二维码可能携带口令，只分享给允许加入房间的人。

### 使用 Android App

按 [Android 指南](../mobile/README.md)安装后，手机与电脑连接同一局域网，打开 App 等待约三秒发现结果：

- 首次仅一个兼容服务：自动连接；多个服务：选择目标服务。
- 以后优先寻找上次选择的服务 UUID，IP 改变后仍可识别。
- 找不到原服务时不会擅自切换其他服务。点击「重新发现」重试，或从右上菜单「切换服务器」重新选择。
- 需要口令时输入后点击「加入」。错误口令会显示失败；同 IP 每分钟只允许五次失败尝试，达到限制后请稍候。

发现失败时可选择「手动连接」，输入完整地址，例如 `http://192.168.1.10:8787` 或 Tailscale HTTPS 地址。手动连接用于访问或排查，不能证明自动发现成功。当前启动流程仍会发起 UDP 发现，纯手动地址场景下重启 App 后可能需要重新输入地址。

## 3. 昵称、设备与登录

为设备设置容易识别的昵称，例如「我的手机」「办公电脑」。App 菜单提供「修改昵称」，网页加入时可设置昵称。昵称用于显示，不是账号或身份凭据。

两端都在线时，应能在设备列表里看到对方。同一浏览器的多个标签可能显示为同一个设备；清除浏览器数据或 App 数据会丢失本地身份。App 保存设备密钥和昵称，并按服务 UUID 在系统安全存储保存认证 Cookie，不保存口令明文。

服务端重启会让原会话失效；启用口令的房间需要重新输入口令。服务 UUID 只有在服务端身份目录保留时才能跨重建保持稳定。

## 4. 群聊与私信

默认发送给所有设备。网页输入文字，按 Enter 发送、Shift+Enter 换行；App 输入后点击发送按钮。对端应立即看到消息。

发送私信时先在设备列表选择目标，确认「发送给」或接收者标记，再发消息。网页可选择多个设备，App 当前选择单台设备；恢复群聊时网页点击「改为群发」，App 选择「所有设备」。私信只在相应设备的会话中展示，离线目标不能作为可靠离线收件箱使用。

## 5. 文件、图片和文件夹

网页点击「添加文件」，也可拖入文件或粘贴图片。拖入文件夹会先打包成 ZIP；大文件夹需考虑浏览器内存和打包时间。Android 用「发送文件」打开系统文件选择器，每次选择一个文件，不提供网页的文件夹打包功能。

发送前检查接收者。上传时查看进度，完成后对端出现文件消息。默认上限 500 MiB，以服务端 `/api/info` 返回的 `maxUploadMb` 为准。

网页点击文件消息下载，位置由浏览器管理。App 点击文件消息后先下载到临时文件，再打开系统保存入口；选择目录、确认保存后文件才导出。取消系统保存时，可再次点击消息下载。请在服务端清理或重启前保存需要保留的文件。

### 上传中断与取消

App 先将待传文件复制到私有目录，保留任务记录；网络中断或 App 重启后点击「继续」。服务端仍保留会话时从已有偏移继续；会话过期或服务端重启后需重新上传。点击「取消」会清理任务及待传副本，完成后也会清理副本。

网页刷新后如需恢复上传，按界面提示重新选择原文件。上传断点不等于下载断点：App 下载失败需要点击文件消息重新下载，不会从下载中断处继续。

## 6. 断线、换网和重启

App 在前台启动、网络变化和恢复前台时检查连接；不保证后台或锁屏期间持续在线。断开时先恢复到可访问服务端的网络，再观察连接状态，必要时点「重新发现」。网页会自动重连，电脑 IP 改变后可重新扫描加入二维码。

服务端重启后，设备可重新连接，但之前的消息、文件索引和上传文件不会恢复。App 保留的未完成上传任务可以重新上传。若 Docker 重建后被识别为新服务，查看[服务身份持久化](deployment.md#服务身份持久化)。

## 7. 不同网络下怎么用

同一局域网使用 UDP 自动发现。跨网络时需要自行部署可达的 HTTPS 服务，或让双方加入同一个 Tailscale 网络，再手动输入 HTTPS 地址。Tailscale 实例与局域网实例默认是两个独立房间，连接不同实例的设备不会互相出现。

发现或连接失败请进入 App 的「连接排查」，并按[排错指南](troubleshooting.md)分别检查 HTTP 和 UDP 路径。
